    자린고비의 목표를 세웠어요

    Solution 1

    생활형 절약 챌린지

    리디자인에서는 그 콘텐츠를 하나의 브랜드 인상으로 연결하는 데 집중했습니다.

    메인과 서브페이지 전반에 반복 적용해 페이지를 이동해도 같은 분위기가 이어지도록 구성했습니다.

    03 MAIN EXPERIENCE

    브랜드의 첫인상을

    하나의 흐름으로 설계하기

    메인페이지는 단순히 아티스트와 콘텐츠를 모아두는 화면이 아니라,
    플레디스라는 브랜드를 처음 인식하는 시작점이 되도록 구성했습니다.

    우주형 히어로에서 시작해 Artist, MV, Album, Audition으로 이어지는 흐름을 만들고,
    사용자가 페이지를 내려가며 플레디스의 분위기와 콘텐츠를 자연스럽게 따라가도록 설계했습니다.

    1. 01 HERO 플레디스의 첫인상을 여는 우주형 비주얼

      정지된 대표 이미지 대신 밤하늘 영상 무드를 배치해
      플레디스라는 이름이 가진 별의 이미지를 먼저 전달했습니다.

    2. 02 ARTIST 소속 아티스트를 한눈에 보여주는 구간

      개별 아티스트를 깊게 설명하기보다,
      플레디스에 어떤 아티스트들이 함께 있는지 빠르게 인식하도록 배치했습니다.

    3. 03 MV 영상으로 이어지는 미디어 탐색 구간

      MV 썸네일을 클릭하면 YouTube 영상이 팝업으로 재생되도록 구성해
      페이지를 벗어나지 않고 음악과 퍼포먼스를 바로 경험할 수 있게 했습니다.

    4. 04 ALBUM 앨범을 넘기는 작은 재미

      클릭할 때마다 다른 앨범으로 전환되도록 구성해
      정적인 앨범 목록보다 가볍게 둘러보는 재미를 더했습니다.

    5. 05 AUDITION 브랜드 경험을 참여 행동으로 연결

      사이트의 마지막 흐름을 오디션으로 연결해
      플레디스가 새로운 가능성을 찾는 회사라는 인상을 남겼습니다.

    05

    IMPLEMENTATION STRUCTURE

    시나리오와 화면 연출을 분리해
    수정 가능한 게임 엔진으로 만들다

    게임의 시나리오는 Ink 스크립트로 작성하고, 화면 출력과 연출은 JavaScript 엔진이 처리하도록 구조를 분리했습니다.
    대사, 선택지, 배경, 캐릭터, CG, 효과는 스크립트 안의 태그로 관리하고, 게임 엔진은 해당 태그를 해석해 화면 요소를 동적으로 출력합니다.

    이를 통해 시나리오를 수정하거나 장면을 추가할 때 전체 코드를 다시 작성하지 않아도 되는 구조를 만들었습니다.

    POINT 01

    INK SCRIPT

    스토리와 선택지를 스크립트로 관리

    대사, 선택지, 루트 분기, 변수 조건을 Ink 스크립트로 작성해
    시나리오 구조를 코드에서 분리했습니다.

    POINT 02

    TAG BASED DIRECTION

    태그로 장면 연출을 선언

    배경, 캐릭터, CG, 사운드, 효과를 태그로 지정하고
    JavaScript 엔진이 해석하여 화면에 반영하도록 구성했습니다.

    POINT 03

    JS GAME ENGINE

    스크립트를 실제 화면으로 출력

    inkjs로 스토리를 실행하고,
    JavaScript 엔진이 현재 장면에 맞는 UI, 대사창, 선택지,
    캐릭터와 배경을 동적으로 렌더링합니다.

    POINT 04

    SAVE & STATE

    플레이 상태를 저장하고 복원

    본 엔딩 기록이 유지되도록 구성했습니다.

    제작 과정에서는 분기 도달 여부, 기존 세이브 충돌, 선택지 UI 오류, 사운드 자산 부족 등
    실제 플레이 과정에서 발생할 수 있는 문제를 테스트하며 개선했습니다.

    ISSUE 01

    ROUTE BALANCE

    도달 불가능한 루트와 엔딩

    문제

    호감도 기준이 실제 플레이 흐름과 맞지 않아
    특정 루트 진입이 어려웠습니다.

    해결

    inkjs 헤드리스 시뮬레이션으로
    플레이 패턴별 자동 검증을 진행했습니다.

    결과

    루트 진입과 엔딩 기준을 재조정해
    모든 루트가 엔딩까지 이어지도록 개선했습니다.

    ISSUE 02

    SAVE GUARD

    구조 변경 후 세이브 충돌 위험

    문제

    스토리 구조 수정 후 기존 세이브 데이터와
    새 스토리 구조가 충돌할 위험이 있었습니다.

    해결

    storyV 버전 가드와 LoadJson try/catch,
    안전 폴백 처리를 추가했습니다.

    결과

    잘못된 세이브 데이터로 인한
    크래시를 방지할 수 있었습니다.

    ISSUE 03

    SOUND DESIGN

    음악 게임인데 음원이 없는 문제

    문제

    음악을 주요 소재로 삼았지만
    별도로 사용할 수 있는 음원 자산이 없었습니다.

    해결

    Web Audio API를 활용해 별도 음원 파일 없이
    장면별 배경음을 코드로 생성했습니다.

    결과

    음원 파일 없이도 장면별 분위기를 만들고
    게임의 몰입감을 높일 수 있었습니다.

    랜딩에서 플레이까지,
    하나의 흐름으로 연결한 비주얼노벨 웹

    플레이리스트 : 우리 사이의 음표는 게임의 분위기를 소개하는 랜딩페이지에서 시작해
    선택지, 호감도, 루트 분기, 세이브, 멀티엔딩이 작동하는 비주얼노벨 게임으로 이어지는 프로젝트입니다.

    이번 프로젝트를 통해 비주얼노벨에서 중요한 것은 장면을 많이 보여주는 것이 아니라,
    사용자의 선택이 관계를 바꾸고 그 관계가 다시 루트와 엔딩으로 이어지는 구조를 설계하는 것임을 배웠습니다.
